## Description

> **Phase:** Foundation (Task 00 of 05) · **Rule:** every task leaves the repo bootable — no task is complete until `kubectl get pods` shows all pods Running and the verification step passes.

**Goal:** One command brings up the entire system on Docker Desktop Kubernetes. Every service is a "hello world" that proves its container runs.

## What to build

| Component | What it does at this stage |
|---|---|
| `services/core-api/` | Minimal .NET Core Web API. `GET /` → `{ "service": "core-api", "status": "running" }` |
| `services/receipt-service/` | Minimal Python HTTP server (Flask/FastAPI). `GET /` → `{ "service": "receipt-service", "status": "running" }` |
| `services/ingestion-service/` | Minimal .NET Core HTTP server (ASP.NET Core Minimal API). `GET /` → `{ "service": "ingestion-service", "status": "running" }` |
| `frontend/` | Vite + React. Default welcome page. Builds and serves via nginx in Docker. |
| `k8s/namespace.yaml` | Creates `expense-tracker` namespace. |
| `k8s/postgres.yaml` | Postgres 16 StatefulSet + PVC. No tables yet. |
| `k8s/rabbitmq.yaml` | RabbitMQ Deployment + Service, management UI accessible. |
| `k8s/*.yaml` (services) | Deployment + ClusterIP Service for each of the 4 app services. |
| `Makefile` | `make build` / `make deploy` / `make status` / `make logs svc=core-api`. |

## NOT in scope

No routing between services, no database tables, no business logic, no auth.
